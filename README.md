# AI 全流程 Minecraft TaCZ 枪包制作 · 模型能力测试项目

> 这个仓库不只是一个枪包，它是一份**给大模型的考卷**。
> 每一把枪都是一道题：给一个模型「从一个想法做到能在游戏里开火的成品」，看它能不能在**没有文档、没有编辑器、没有外网**的条件下，把一个没人为它准备过的格式（TaCZ 的 poly_mesh 枪械格式）从头啃通。
>
> **第一把枪：R3 Carbine（rifle3）** —— 由 `deepseek-v4.1-flash-1017` 在 DeepSeek Harness 里完成。

## 为什么这是个能力测试

TaCZ（Timeless and Classics Zero）是 Minecraft 上一个主流枪械模组，但它**没有公开的模型格式文档**。一个枪包出错的方式几乎全是**静默失败**：

| 你写错了什么 | 游戏的反应 |
|---|---|
| `format_version` 写成 `1.21.0`（而非 `1.10.0` / `1.12.0`） | 骨骼解析失败，什么都不发生 |
| `model_type` 写成 `meshy`（日志里就是这么写的） | 模型完全不加载，无报错 |
| poly_mesh 角点顺序不是 `[位置, 法线, UV]` | 贴图噪点，或直接 `ArrayIndexOutOfBoundsException` |
| `extended_mag_ammo_amount` 写成 1 项（要求正好 3 项） | Gson 异常 → **整把枪从索引里消失**，物品退化成紫黑格 |
| 自带瞄具挂在 `scope_default` 上 | 不报错，只是永远可见 → 装上瞄具后**两个镜子叠在一起** |
| 多边形的面绕序反了 | Blender 里看不出来，进游戏是**黑面** |

没有一行日志告诉你哪里错了。所以这道题真正考的是四件事：

1. **能不能把机器当证据用。** 项目里所有关于 TaCZ 内部行为的结论，都是从 jar 的**字节码常量池**里读出来的（本机没有 JDK、没有 javap、没有外网、没有 wiki 可查）。
2. **能不能自己造裁判。** 因为系统不说话，所以每一步都要先设计一个**离线可验证的判据**（`tools/checker/tacz_check.py` 对任意枪包跑全套检查，当前 0 error / 0 warning）。
3. **能不能把「看起来对」换成数字。** 第一人称位置、镜孔黑边比例、附件挂点，全部是与官方 112 把枪做语料**统计标定**之后才敢落地（见 `docs/踩坑与解法.md` 的 P4「判据必须在真实语料上标定」）。
4. **能不能在长任务里保持交付。** 从空目录到可安装的 zip 跨越多轮迭代，每一轮的结论都写成了文档，而不是烂在会话里。

## 第一把枪的成绩单

### 成品

- `dist/Rifle3_GunPack_1.0.0.zip`（1.15 MB，51 个文件，md5 `4d4e4318…`）
- `dist/7x46_GunPack_1.0.0.zip`（11 KB，随枪配套的架空弹药）

| 项 | 数字 |
|---|---|
| 全长 | 704 mm（加长消焰器尖到尾垫） |
| 源模型 | 54 个网格 / 64 344 三角面 |
| 导出模型 | **111 506 三角面**，零精度损失（poly_mesh 直接存三角面） |
| 骨骼 | 45 根（枪体 / 弹匣 / 枪机 / 拉机柄 / 空仓挂机 / 扳机 / 快慢机 / 释放钮 / 挂点 / 视角） |
| 动画 | 9 个，Bedrock 1.8.0，30 fps 逐帧烘焙 |
| 附件 | 4 个自带（枪口 / 瞄具 / 枪托 / 扩容弹匣）+ 兼容官方 6 类 |
| 弹药 | 架空 **7×46 mm**，30 发匣，扩容 60/75/90，可合成 |

### 它做对了什么（都可以逐条验收）

**换弹动画照抄官方 m4a1。** 不是自己编的——把官方 `m4a1.animation.json` 的骨架、节奏、音效节拍逐通道对齐，再换成自己的几何。左手**真的抓着弹匣一起走**（弹匣挂在手骨子树下，`lefthand` 的 position 通道叠了弹匣位移），不是「原力换弹」。空仓换弹最后会拉一下枪机。

**抛壳口是真开孔。** 上机匣右侧有一个 70×18 mm 的窗口，透过它能看到枪机。这一项最初是错的——布尔切完之后装饰板的内层盖还留在窗口中间，渲染图和游戏里都只看到浅坑。最后是**用射线打过去**才发现：窗口里先打到的是 `UR_detail @ y −24.6`，而不是 `Bolt @ −18.5`。

**配件改装界面是横着的。** 最初枪在配件界面里竖着怼镜头。根因不在布局代码，而在 `refit_view` 这根骨**只写了 pivot 没写 rotation**——TaCZ 用 `getPositioningNodeInverse()` 反解这条骨链来摆枪，官方 490 把枪的 `refit_view` 全是 `[0,90,0]`。

**自带瞄具不会和配件叠成两个镜子。** TaCZ 的 `allAttachmentRender()` 明确**跳过** `SCOPE` 类型（`type != NONE && type != SCOPE`），所以 `scope_default` 这根骨永远不会被隐藏。改挂到 `sight`（有 `scopeHiddenRender` 接管）之后，装镜即隐藏，两条分支都只画一个镜子。

**开火时手臂不翻飞。** `shoot` 是**叠加（additive）**动画，值会加到 `static_idle` 上。之前在里面也写了手部姿态 96°，叠加后变成 192°，一开枪手臂就上下甩。现在 `shoot` 里只有 root / 枪机 / 扳机。

### 它还没做到的

- **没进游戏逐条目视验收。** 上面所有结论来自离线自检、Blender 内预览、射线检测、与官方 112 把枪的字段级比对、以及字节码取证。真正只有游戏能回答的（抛壳口的实际观感、四件配件的拆装手感）还没人看过。
- **没有手部模型。** 第一人称的手是 TaCZ 用原版玩家手臂画的，本包只提供 `righthand_pos` / `lefthand_pos` 两根骨的位置与握姿旋转。
- **依赖一个额外模组。** poly_mesh 格式需要 **TML（Tacz Mesh Loader）0.1.8**，原版 TaCZ 不认。

## 怎么验收这把枪

1. **装环境**：Minecraft 1.20.1 + Forge 47.4.10 + TaCZ `1.1.8-hotfix2` + **TML `tacz-mesh-loader-forge-1.20.1-0.1.8`**（没有它 poly_mesh 完全不加载）。
2. **装包**：把 `dist/Rifle3_GunPack_1.0.0.zip` 丢进 `<实例>/tacz/`，**重启游戏**（`/tacz reload` 对 gun index 不一定够）。
3. **找枪**：创造模式物品栏的 TaCZ 页签里找 **R3 Carbine / R3 卡宾枪**，弹药是 **7×46 实验弹**。
4. **照 `docs/枪包说明.md` 第三节的 10 条清单逐条看。**

离线自检可以先跑一遍（不需要游戏）：

```bash
python tools/checker/tacz_check.py dist/Rifle3_GunPack_1.0.0.zip
# -> Rifle3_GunPack_1.0.0.zip   0 error(s), 0 warning(s)
```

## 给下一个模型（或下一个人）

如果你要接这把枪往下做，先读 `docs/踩坑与解法.md`。它不讲代码，讲**为什么**：

- **P1 沉默系统**：这类系统把异常降解成「没有效果」，所以你必须有自带裁判。
- **P2 数据驱动的引擎把名字当 API**：骨骼名 / 系统保留名 / tag 名 / 类型名是四种东西，写错不报错。
- **P3 语义先于数值**：替换 vs 叠加、父子 vs 兄弟、绝对 vs 增量——先答语义再调数字。
- **P4 判据必须在真实语料上标定**：官方自己也大量出框，所以「出框」不是失败判据。

重建链（只有第 1 步需要 Blender；2–5 是纯 Python，全程 < 6 秒）：

```bash
cd blender
blender -b rifle3.blend --python r3_export_tacz.py   # 几何 -> geo.json
python r3_att_geo.py                                  # 附件几何（重定原点到挂点）
python r3_anim.py                                     # 动画烘焙
python r3_pack.py                                     # 打包成 zip
python ../tools/checker/tacz_check.py ../dist/Rifle3_GunPack_1.0.0.zip
```

## 下一把枪要考什么

第一把枪已经证明：在没有文档的格式里，一个模型靠「读字节码 + 造裁判 + 用数字说话」能做出可安装的成品。接下来这份考卷可以按难度往上加：

- **多把枪 + 共用弹药体系**（考架构，不考单点技巧）
- **有机曲面 / 布料 / 手部模型**（考几何，而不是考硬表面建模）
- **完整的动画状态机 + Lua 脚本**（考系统集成）
- **从零复现一个官方枪包的全部行为**（考逆向的完整度，而不是够用即可）
