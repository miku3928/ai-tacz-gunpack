## 0. 五分钟看懂

### 这个工程是什么

`rifle3.blend` 是一把程序化建模的 690 mm 卡宾枪（62 个网格 / 11 万三角面）。
我们要做的事只有一件：**把它变成一个 TaCZ 枪包 zip**，包含

* 一个能开火、能换弹、能开镜的枪；
* 4 个可拆装附件（消焰器 / 瞄准镜 / 枪托 / 扩容弹匣）；
* 9 个 Bedrock 动画（含换弹，左手要真的抓住弹匣）；
* 一个架空的 7×46 mm 弹药（另一套命名空间，原样并入）。

### 三个最容易踩死的坑（先记住，细节在 §10）

1. **`model_type` 必须是字符串 `mesh`**。TML 注册的字符串键就是 `mesh`，但它的日志文案写的是 "meshy" —— 照日志写就永远加载不出来，且没有任何报错。
2. **`extended_mag_ammo_amount` 必须正好 3 项**（对应扩容弹匣 1/2/3 级）。写成 1 项 → Gson 抛异常 → **整个 gun index 加载失败** → 物品退化成紫黑占位格。
3. **`shoot` 是 additive 叠加动画**（`runAnimation("shoot", track, true, ...)`）。它里面**绝对不能出现手骨通道**，否则 96° 的手部姿态被叠成 192°，一开枪手臂就会上下翻飞。

## 4. 坐标与单位（三个空间，别混）

| 空间 | 单位 | 原点 | 轴向 |
|---|---|---|---|
| **Blender** | 毫米（`r3_lib.S = 0.001` 转成米） | 世界原点 = 膛线轴中点附近 | +X 沿枪身（枪口在 x≈0、托底 x≈690），+Y 左，+Z 上 |
| **TaCZ model unit** | 1 unit ≈ 19.07 mm | 由 `OFFY` 抬到枪身中部 | **−Z 枪口 / +Z 托底 / +Y 上 / +X 右侧（抛壳侧）** |
| **Bedrock JSON position 通道** | **就是 model unit** | 同上 | 同上（JSON 里再乘 0.0625 由引擎自己做） |

### 映射公式（`r3_export_tacz.py:30-46`）

```python
U = 52.4476     # model units per metre
CX = 0.345      # blender x 基准（m）
OFFY = 12.0     # 抬高，让枪身落在 y≈12 附近

tx = -y_m * U
ty =  z_m * U + OFFY
tz = (x_m - CX) * U
法线：TN(n) = (-n.y, n.z, n.x)
```

* **Y 是镜像的**：blender 的 +Y（左）变成模型 −X。所以**blender −Y = 模型 +X = 抛壳侧**。
  这就是 `laser_pos` 在 blend 里写 `y = -28`、导出后落在 x `+1.46853` 的原因。
* **镜像会反转缠绕序**：exporter 的 `emit()` 用 Newell 法线对比存储法线，不一致就 `corners[::-1]`。
  `work/check_wind.py` 是这条的守卫：当前 **55753 面，0 反绕序，0 退化**。

### 动画里另有一个常数

`r3_anim.py:19` 的 `K = 0.0524476`（model unit per **mm**），是 `U/1000`。
用它把 mm 直接写成通道值：`MAG_FULL = 165 mm × K = 8.334`。

### position 通道的语义（重要）

* `Animations.writeBedrockTranslation` 对每条关键帧乘 **0.0625**（=1/16），
  所以 **1 个 JSON position 单位 = 1/16 block = 1 个 model unit**。
* 通道 `[x, y, z]` 对世界平移是 **1:1**（`work/chan_probe.py` 实测），但 **Y 要取反**
  （`ModelTranslateListener.update` 里对 Y 做了 `fneg`）。
* 曾经有 12 小时把 JSON 值当 block 用（缺 1/16），导致所有平移放大 16 倍 ——
  `work/fk2.py` 的注释里记着这段历史，改之前先读它。

### 5.2 为什么是这个结构

* **`root` 的 pivot 在肩部不是原点**：绕 `[0,0,0]` 转会像绕着扳机下方的一点甩整把枪。
* **`idle_view` 独占第一人称位置**：TaCZ 把整个模型平移 `-idle_view`，相机就坐在那一点上，
  **不做任何缩放**。所以"枪在屏幕上多大"完全由 idle_view 离零件多远决定。调它就是 §9.1 的工具。
* **`sight` 而不是 `scope_default`**：见 §7.3，这是全篇最反直觉的一条。
* **手骨是空骨**：TaCZ 给 `righthand_pos` / `lefthand_pos` 注册 functional renderer，
  在它们的**世界矩阵**上画**原版玩家手臂**。骨上挂的任何几何在渲染时都会被丢掉。
  手骨链是从官方 m4a1 的三骨链
  （`gun_and_righthand` → `righthand` → `righthand_pos`）压成两级解出来的，
  然后整体平移到"握把/护木中心 + 官方 37/20 把枪的中位偏移"。
  推导在 `r3_export_tacz.py:118-142` 的注释里，别重算。
* **`righthand` / `lefthand` 的 scale 是 `[1, 1.5, 1]`**：官方就这么写的，
  而且 **scale 会拉伸子骨的 pivot**，求解局部 pivot 时必须用 `R·S·lc`，否则差 15 个单位。

### 5.3 骨骼表怎么改

`r3_export_tacz.py:115` 起是 `BONES` 列表，每项 `(name, parent, pivot[, rotation])`。
第 4 项 rotation 只有 `refit_*` 用（其它骨靠动画驱动）。
pivot 用 `P3(x_mm, y_mm, z_mm)` 从毫米写，避免手算。

`BONE_OF`（`r3_export_tacz.py:75-105`）决定**哪个 mesh 落到哪根骨**：

```python
DEFAULTS = {                      # 可拆装件：gun 上留一份副本，装在 <type>_default 上
  'muzzle': ('MuzzleBrake', 'MuzzleBore'),
  'scope':  ('Optic','OpticGlass','OpticMount','Cap','Cap.001'),   # → 实际覆盖成 'sight'
  'stock':  ('StockFrame','Cheek','StockGap','StockDet','ButtPad','ButtRibs'),
}
MAGS = {                          # 两个弹匣体，游戏按 extended_mag_level 显示其一
  'mag_standard':   ('Magazine','MagFloor','MagSlot','MagNeck'),
  'mag_extended_1': ('MagazineBig','MagBigFloor','MagBigSlot','MagBigNeck'),
}
BONE_OF.update({'Bolt':'bolt','ChargingHandle':'charge_handle',
                'BoltCatch':'bolt_catch','Trigger':'trigger',
                'Selector':'selector','MagRelease':'mag_release'})
# 其余全部落 'gun'
SKIP = ('Backdrop','Cube','Plane','Hand_R','Hand_L')
```

`SKIP` 里 `Hand_R` / `Hand_L` 是早期"自己雕一双手"的遗留手套网格，**不导出**
（TaCZ 会画原版手臂，自己的手会变成第二双错位的手）。

## 6. 动画系统

### 6.1 格式

* 文件：`assets/rifle3/animations/rifle3.animation.json`
* 顶层：`{"format_version": "1.8.0", "animations": {…}}`
* display 里的 `\"animation\": \"rifle3:rifle3\"` 指向它（**不是** `animations/gun/`）。
* 时间单位秒，角度单位度，position 单位 model unit。
* **没有 loop 字段 = 播一次**。

### 6.2 关键帧格式的选择（为什么烘焙）

TaCZ 的 `AnimationKeyframesSerializer` 也能解析对象形式
（`{"post": [...], "lerp_mode": "catmullrom"}`），但**官方 55 把枪全部是裸三元数组**，
那是被证明能在游戏里播的形态。所以我们**稀疏地写**（用 `kf()` 带 catmullrom），
导出时 `bake()` 采样到 1/30 s 网格：

```python
FPS = 30.0
def bake_channel(ch, length):
    # 已经是 list 的静态值原样返回
    # 否则按 1/30 采样，catmull 段内 CLAMP 到端点防过冲
    # 全段无变化的通道直接塌成静态 [x,y,z]
```

**catmull 段内 clamp 是必须的**：弹匣是"先停住再加速离开"的形状，
不过冲钳位的话，静止段会自己往前漂。

### 6.3 九个动画

| 动画 | 长度(s) | 通道 | 备注 |
|---|---|---|---|
| `static_idle` | 0.0667 | lefthand, righthand, root | 手摆好，LOOP |
| `static_bolt_caught` | 0.6667 | bolt, bolt_catch, 手 | 空仓挂机态，LOOP |
| `shoot` | 0.6333 | bolt, root, trigger | **additive，刻意没有手** |
| `draw` | 0.8000 | 手, root | |
| `put_away` | 0.4333 | 手, root | |
| `inspect` | 2.5000 | bolt, charge_handle, 手, root | |
| `inspect_empty` | 2.3500 | bolt, 手, root | |
| `reload_empty` | 2.3750 | bolt, bolt_catch, lefthand, mag_release, magazine, righthand, root | 空仓换弹 |
| `reload_tactical` | 2.2000 | bolt, lefthand, mag_release, magazine, righthand, root | 膛内有弹 |

这就是 `default_state_machine.lua` 会调的 9 个。
state machine 是**官方 jar 里内置的 lua**（已解包到 `work/dsm.lua`，748 行），
它按 `data.reload.feed.*` / `cooldown.*` 决定混合与时长。

### 6.4 手通道的规则（两条，必须记）

1. **`shoot` 里绝对不能有 `righthand` / `lefthand`。**
   `dsm.lua:323` 是 `runAnimation("shoot", track, true, PLAY_ONCE_STOP, 0)`，第三参 `true` = additive。
   手骨的 96° 旋转会叠在自己身上变成 ~192°，玩家看到的就是"一开枪整条手臂上下翻飞"。
   官方 `m4a1.animation.json` 的 shoot 通道只有 root / bolt / camera / constraint —— 没有手。
   `validate_pack.py` 里有硬检查（`ADDITIVE = ("shoot",)`），别删。
2. **其余 8 个动画必须有手通道。** 少一个，那只手就退回默认姿态，看起来像没握住枪。

### 6.5 换弹：抄官方 m4a1

`reload_empty` 的时间分段（`r3_anim.py:166`）：

```
drop       = (0.22, 0.50)   弹匣开始下滑 -> 完全脱离
back       = 0.92           新弹匣到位（藏）
insert     = (0.92, 1.32)   新弹匣入井
bolt_release = 1.78         按空仓挂机、枪机复进
tilt_end   = 2.05           枪身回正
L          = 2.375          总长（= data.reload.cooldown.empty 2.05 之后留 0.325 s 尾巴）
```

`reload_tactical` 同构但压缩（`0.18 / 0.42 / 0.82 / 1.20 / None / 1.92 / 2.2`），没有拉栓。

**枪身倾转**（`root.rotation`，峰值 `[-12, -11, -26]` @0.70）：
三轴全负 = 枪口上抬（X 负）+ 偏航向左（Y 负）+ **向右倾（Z 负）**。
这是照 m4a1 的 `[-19.56, -19.13, -22.22]` 缩了约 60% 抄的。
**方向不能反**：反了就是"向左倾、弹匣从右下方出来"，与现实相反，
而且弹匣会撞机匣前壁（见 §10.9）。`work/flip_proof.py` 是这条的判据脚本：
它打印"弹匣质心屏幕 x − 机匣质心屏幕 x"，负值 = 弹匣在屏幕左侧（正确）。

**左手抓弹匣**（`HAND_GRAB = [-0.4356, -4.1511, 11.1370]`，`r3_anim.py:71`）：

* 我们的 `magazine` 和 `lefthand` 是 `gun` 下的**兄弟**，不是父子
  （官方 m4a1 里弹匣挂在 `mag_and_lefthand` 之下，手和弹匣同子树，天然跟随）。
  所以只能在动画里给 `lefthand.position` 加偏移，把弹匣的位移**加上** `HAND_GRAB` 一起写。
* 这个偏移**不能**用 rest pose 算。每个动画都写 `LH_ROT (97/-29/-147°)`，
  可见的手离 rest 位置很远。正确做法：在**动画姿态下**用 `work/attach.py` 求
  「手套网格质心 ↔ 弹匣质心」的差。
  曾经用 rest pose 算出 `[-0.166…]`（差了一个数量级），结果就是"原力换弹"。
* 判据脚本：`work/glove_dist.py`（世界距离）与 `work/glove_screen.py`（屏幕像素距离）。
  当前换弹全程手套↔弹匣世界距离 0.00（t=0.20/0.30/0.40/1.10/1.30），
  提升段 4.30（弹匣已隐藏，只看手），收尾回到护木 11.89。

## 7. 配件系统

### 7.1 名字驱动，全靠字符串拼接

`BedrockGunModel` 里所有挂点都是运行时拼字符串：

| 骨名 | 作用 |
|---|---|
| `<type>_pos` | 装上的附件画在这里（`scope_pos` / `muzzle_pos` / `stock_pos` / `grip_pos` / `laser_pos`） |
| `<type>_default` | 枪自带的那个零件，装上附件后自动隐藏 |
| `mag_standard` / `mag_extended_1..3` | 弹匣本体，按 `extended_mag_level` 只显示一个 |
| `sight` / `sight_folded` / `mount` | 瞄具相关的三态骨（见 §7.3） |
| `attachment_adapter` / `ar_stock_adapter` / `laser_adapter` | 带 adapter 声明的附件挂这里 |

**没有 `grip_pos` / `laser_pos` 骨，官方的握把和激光在配件界面里根本不会出现。**

### 7.2 附件链（任一环断掉都是静默失败）

```
gun data.allow_attachment_types = ["scope","stock","muzzle","grip","laser","extended_mag"]
        ↓
data/rifle3/tacz_tags/attachments/allow_attachments/rifle3.json
   ["#rifle3:extended_mag","#rifle3:muzzle","#rifle3:scope","#rifle3:stock",
    "#tacz:extended_mag","#tacz:ammo_mod_no_he", …共 12 项]
        ↓
每个 tag 文件列 item id  →  data/rifle3/index/attachments/<id>.json（name/display/data/type/sort）
        ↓
display json（model/texture/slot，scope 还要 zoom/scope/fov）
data json（weight/ads/recoil/…）
```

跨包引用（`#tacz:extended_mag`、`#tacz:scope_scope` 等）是**故意的**：
官方有 12 个握把、9 个枪托、19+ 个瞄具、扩容弹匣 2/3 级、hp/fmj 弹模，
只有引用官方 tag 才能全部兼容。`validate_pack.py` 里有 `CROSS_TYPE` 映射表，
把跨包 tag 映射到附件类型再校验 `allow_attachment_types`。

**4 个自己的附件**（`r3_pack.py:70` 的 `ATTACHMENTS` 表）：

| id | 类型 | 来源 | 图标 | 说明 |
|---|---|---|---|---|
| `muzzle_std` | muzzle | `muzzle_std_geo.json` | 64px | R3 加长消焰器 |
| `scope_std` | scope | `scope_std_geo.json` | 64px | R3 1-4x，**5 根骨** |
| `stock_std` | stock | `stock_std_geo.json` | 64px | R3 镂空枪托 |
| `mag_ext_1` | extended_mag | **无模型** | 32px | 几何在枪的 `mag_extended_1` 骨上，`extended_mag_level: 1` |

### 7.3 最反直觉的一条：自带瞄具必须挂在 `sight`，不是 `scope_default`

`allAttachmentRender()` 的循环条件是 `type != NONE && type != SCOPE` —— **SCOPE 被跳过**。
后果：一个叫 `scope_default` 的骨**永远不会被隐藏**，你装任何瞄具都会叠在它上面 → 两个镜子。

真正被隐藏的是 `sight` 系：

```java
// BedrockGunModel.<init> 里
sight        -> scopeHiddenRender(lambda$new$15)   // visible = isEmpty(scope)   ← 没装瞄具时显示
sight_folded -> scopeHiddenRender(lambda$new$13)   // visible = !isEmpty(scope)  ← 装了瞄具时显示
mount        -> scopeHiddenRender(lambda$new$9)    // visible = !isEmpty(scope) && renderMount
```

所以：**自带瞄具几何 → `sight` 骨**，同时 `builtin_attachments: {"scope": "rifle3:scope_std"}`
让它一进游戏就是"装着瞄具"的状态 → 自带瞄具永久隐藏，由 `scope_std` 附件绘制。
一套几何，两个用途，永不重叠。

### 7.4 瞄准镜不是形状，是一组节点

TaCZ 把世界先画，再把枪盖上去，**`ocular` 骨轮廓内的一切挖掉**（stencil）。
所以一个能开镜的瞄准镜必须带 5 根骨（`r3_att_geo.py`）：

| 骨 | 内容 |
|---|---|
| `scope_body` | 镜筒本体（我们的几何） |
| `ocular` | 目镜圆盘，**只写 stencil 缓冲** —— 玩家透过它看世界 |
| `ocular_ring` | 圆盘外的圆环，遮住 stencil 边缘 |
| `division` | 分划板（细十字 + 刻度），`M_Steel` 色 |
| `scope_view` | **空骨，pivot 就是眼点** |

**孔径 ≠ 镜筒内径**。黑边 = (后罩轮廓 − 孔)。
最初把孔设成 11 mm 的膛线孔（0.577 unit）而后罩是 1.1434 unit，
黑边宽得和画面本身一样 —— 玩家看到的就是"糊住屏幕的一块灰板"。
官方 8 个瞄具的环外径只有目镜的 **1.01–1.13 倍**，黑边是发丝级。
现在：`APERTURE_R = 1.02`、`RING_OUTER = 1.1434`（= 后罩实测半径）→ 比值 1.12。
eye relief（`scope_view` 到 `ocular` 的 z 差）取 5.3 unit ≈ 101 mm，与官方 `scope_1873_6x` 一致。

镜筒本身在 `work/bore_optic.py` 里用 EXACT 布尔打穿了 r=11 mm 的孔
（`rifle3_prebore_backup.blend` 是那次操作的备份）。**不打穿的话，stencil 孔会直接看进一块金属端盖。**

### 7.5 配件界面（按 Z）的横放

`FirstPersonRenderGunEvent.applyFirstPersonPositioningTransform` 会走
`getRefitAttachmentViewPath(type)` → `getPositioningNodeInverse(path)` → 矩阵插值。
**朝向完全由 `refit_*` 骨的 rotation 决定**，pivot 只决定哪个零件占画面。

官方全部 `[0, 90, 0]` 起（部分派生角度）。我们最初只写了 pivot 没写 rotation →
枪保持第一人称的竖直朝向，"戳到脸里"。
现在 7 根 `refit_*` 都是四元组带 rotation（`r3_export_tacz.py:223-229`）：

```
refit_view               [23.3, 12.17, -0.36]  [0, 90, 0]
refit_muzzle_view        [20.09, 15.2, -3.66]  [0, 120, 0]
refit_stock_view         [23.2, 15.2, 7.97]    [0, 90, 0]
refit_scope_view         [17.77, 17.56, -15.65][0, 50, 0]
refit_extended_mag_view  [17.17, 26.88, -1.42] [0, 90, 35]
refit_grip_view          [23.2, 12.81, -9.86]  [0, 90, 0]
refit_laser_view         [13.95, 20.05, 5.4]   [15, 135, 0]
```

pivot 由 `work/refit_solve3.py` 解析求解（让被选中的零件落在相机 `(0,-0.2,1.45)`，
与 m4a1/ak47/hk416d 同位置），`work/refit_verify.py` 用真实的
`fpv3.positioning_inverse` 复验。**只有真从模型重建时才需要重跑这两个。**

## 8. 打包与自检

### 8.1 `r3_pack.py` 结构

```python
NS = 'rifle3'; GUN = 'rifle3'; VERSION = '1.0.0'
TACZ = work/tacz; PACK = work/pack; OUT = out; ICONS = work/icons
COMPANION_ZIP = ../tacz_sheets/7x46/dist/7x46_GunPack_1.0.0.zip
COMPANION_SKIP = ('gunpack.meta.json',)     # 一个 zip 只能有一个根 meta

premul_resize / make_uv_atlas(141) / make_hud(161) / make_slot(181) / make_icon(188)
build(212) / merge_companion(522) / report(551)
```

* `build()` 第一步就决定 `ammo`：`7x46:7x46`（companion 在）否则 `tacz:556x45`。
  **必须先决定** —— ammo 指向一个不存在的 index，TaCZ 会把整个 gun index 丢掉。
* **条纹 UV 图集**：512×512，材质 i 独占整列 `x=32i..32i+31`，
  poly_mesh 的 uv 全是 `[(2i+1)/32, 0.5]`。
  为什么不用 16×16 小方块：TML 的 `FLIP_UV_V` 会取负 V，采样器可能 clamp，
  竖直匀色的列对 V 约定免疫。这是踩过噪点之后的办法。
* HUD（384×128）和槽位（64×64）图都是 `work/icons.py` 从导出的 geo 渲的，
  所以**换模型后图标自动跟着变**。
* `merge_companion()` 把 7×46 包的 15 个文件**逐字节原样**并进来（只丢根 meta）。
  7×46 是独立命名空间，不要把它改写成 `rifle3:` —— 那样要改它内部所有 id 字符串，没有收益。
  一个 zip 里多个命名空间是**官方允许**的（7 个实证包都这么干：
  `[Tacz1.1.5+]CUST GunsmithPack` 有 emxarms/emxcust/trisdyna 三个）。

### 8.2 `validate_pack.py` 查什么（这道门别拆）

这是唯一能在**进游戏之前**抓到静默失败的东西。分组与代表性检查：

| 节 | 检查 |
|---|---|
| layout | 7 个必需文件存在；`gunpack.meta.json` 的 namespace |
| wiring | **`model_type == "mesh"`**；index.display/data 互相指向；display 的 model/texture/hud/slot/animation 都解析到 zip 内真实文件 |
| bones | 名字唯一、parent 存在、无环 |
| poly_mesh | `normalized_uvs == true`；positions/normals 3 维、uvs 2 维；每个角 `[pos, norm, uv]` 且索引不越界；uvs 必须等于条纹中心 `[(2i+1)/32, 0.5]` |
| anims | `format_version == "1.8.0"`；只动真实骨骼；只有 position/rotation/scale；关键帧是**裸 3 元数组**；不超过 `animation_length`；`sound_effects` 有 effect |
| reload timing | `feed < cooldown`；cooldown 不超过动画长；data 引用的 `reload_*` 动画存在；**`extended_mag_ammo_amount` 必须 3 项正整数**；state machine 会调的 9 个都在 |
| 手 | `righthand_pos` / `lefthand_pos` 存在且父子正确；**`shoot` 不许有手通道**；其余 8 个必须有；不许直接动 `*_pos` |
| attachments | type 合法；display/data/slot 解析；`extended_mag_level` 对应的 `mag_extended_N` 骨存在；**扩容弹匣不许自带模型**；scope 必须有 5 个节点、`scope_view` 必须空、`scope_body` 必须有 poly_mesh；附件 geo 根 pivot 必须是原点；附件不许离挂点太远（说明没重定原点） |
| tags | `allow_attachments` 全是 tag 引用；tag 能解析（本包或跨包）；tag 非空；tag 里的 id 有 index；tag 类型与 index 一致；tag 类型在 `allow_attachment_types` 里；`allow_attachment_types` 每项都有对应挂点骨 |
| ammo | gun data 的 ammo 是 `ns:path`；`data/<ans>/index/ammo/<aid>.json` 存在；**display 路径是 `display/ammo/<display_id>.json`，display_id 本身已带 `_display` 后缀，不要再拼一次**；两套 geo 各至少 1 cube；有 `positioning` 就必须有 ground/fixed/thirdperson_hand；lang 有 `index.name`；recipe 的 result.id/type/材质齐全 |
| textures | 尺寸与 geo description 一致（uv 图集必须是 512×512） |

输出最后一行是 `RESULT: n error(s), m warning(s)`，有 error 时 `sys.exit(1)`。
当前基线：`0 / 0`。

### 8.3 `schema_cmp.py` / `schema_ammo.py`

把生成的 data / display / ammo json 与官方 `m4a1` / `556x45` **逐字段比形状**
（类型、数值数组长度、嵌套 dict 递归）。官方 json 带 `//` 注释和尾逗号，脚本里有
`strip_js()`（字符串感知 tokenizer）先剥掉。
`validate_pack.py` 查"我们自洽吗"，`schema_cmp.py` 查"我们和官方同形吗" —— 两个都要过。

### 8.4 装包

`work/install.py` 用 `shutil.copyfile` 复制（**bash 的 `cp` 会 Permission denied**，
游戏占着文件锁；Windows 上 `Copy-Item` 或 Python 可以）。

## 10. 坑（按"踩到时多痛"排序）

### 10.1 `model_type` 必须是 `mesh`
TML 的 `register()` 里 `ldc "mesh"` → `GunModelTypeManager.registerModelType(String, BiFunction)`，
**但它的日志文案写的是 "Registered TacZ model type: meshy"**。
照日志写 `meshy` → 模型完全不加载，**没有任何报错**。

### 10.2 `extended_mag_ammo_amount` 必须正好 3 项
写 1 项 → `JsonParseException: extended_mag_ammo_amount size must is 3`
→ **整个 gun index 加载失败** → 物品变 `item.tacz.modern_kinetic_gun` + 紫黑格子。
日志原文：
```
[tacz/GunIndexLoader]: Failed to load data file rifle3:rifle3
com.google.gson.JsonParseException: extended_mag_ammo_amount size must is 3
```
这条错误曾存在整整一版包而没人发现，因为当时的自检只查资源路径/骨骼/关键帧，
**不查 JSON 形状与官方是否一致**。现在 `validate_pack.py` 和 `schema_cmp.py` 都查。

### 10.3 `shoot` 里的手通道
见 §6.4。additive 会把 96° 叠成 192°。

### 10.4 poly_mesh 角点顺序是 `[位置索引, 法线索引, UV索引]`
写错 → 贴图噪点，或 `ArrayIndexOutOfBoundsException`。
三角面要补第 4 个角（`corners.append(corners[0])`）。
n-gon 必须先三角化（`emit()` 里 `len(corners) not in (3,4)` 直接丢弃）。

### 10.5 例外的那个"孔"：EXACT 布尔会留下内层盖
`UR_detail` 那块抛壳口装饰板是几层重叠壳体 union 出来的。
EXACT 布尔只切掉了最外层，**内层盖留在窗口中间** —— 从外面看永远是平板，
枪机完全看不见（渲染上表现为"删掉 Bolt 骨的图和没删的图 sha256 相同"）。
修法不是加 cutter，而是 `r3_bolt.py` 的 `open_window()`：直接 bmesh 删掉重心落在窗口矩形内的面。
**"看起来被挡住"时先用射线和面计数取证，不要猜。**

### 10.6 `bpy.ops.object.origin_set()` 不可用
父级带 `matrix_parent_inverse` 时，算子结果会被撤销。
必须手写两步（见 `r3_rig.py` 的 `set_origin()`）：
`mw = o.matrix_world.copy(); delta = mw.inverted() @ pivot` → 逐顶点 `v.co -= delta` →
`new = mw.copy(); new.translation = pivot; o.matrix_world = new`。

### 10.7 `matrix_world` 是懒求值的
改完 parent 不 `view_layer.update()` 就读到旧值。
同理：**隐藏对象 `to_mesh()` 拿到的是未求值网格**，导出前必须 unhide 全部 MESH
（`r3_export_tacz.py` 的 `main()` 第一件事就是干这个）。

### 10.8 不要随手跑 `r3_make.py` / `r3_split.py`
* `r3_make.py` 会 `L.wipe()` 重建整个场景 —— 会抹掉后加的 Bolt / ChargingHandle / BoltCatch / Hand_*。
* `r3_split.py` 现在**跑不了**：它的 `GROUPS` 只有 5 组，不含
  `Bolt / BoltCatch / ChargingHandle / Hand_L / Hand_R`，实测直接
  `RuntimeError: unassigned meshes: [...]`。只有真从 `r3_make.py` 重建时才需要动它。
* 绝对不要用 `--explode`（会保存文件，把工程永久散开）。

### 10.9 换弹的倾转方向
反了 = "向左倾、右手换弹"，而且弹匣会撞机匣前壁（弹匣口本来就比机匣前缘凸出 9 mm，
不能再加任何绕竖直轴的前倾摆动）。
判据只能是数值：`work/flip_proof.py` 的"弹匣质心屏幕 x − 机匣质心屏幕 x"必须为负。

### 10.10 出框不能当失败判据
官方 m4a1 的 reload 全程 NDC x 峰值是 `−3.80..7.23`、y `−22.60..−0.61`；
`spr15hb` 是 `nx −139`、`uzi` 是 `nx +104`。**官方自己大量出框。**
真正该看的是"符号对不对 / 质心差对不对"。

### 10.11 读图工具会缓存 sha256
曾经三张不同内容的图读到同一个 sha256，无法用视觉确认差异。
**判据优先用数值**（md5sum 落盘 + 数值脚本），图只用来做最后的观感确认。

### 10.12 python 里的 `/tmp` 不是 bash 的 `/tmp`
`FileNotFoundError: '/tmp/tunertest/t.zip'`。中间文件一律放工作区内相对路径。

### 10.13 zip 内的 geo 顶层是列表
`g['bones']` 会 KeyError。必须 `geo_root(g)['bones']`
（`geo = g.get('minecraft:geometry', g.get('geometry'))`）。

## 11. 怎么取证 TaCZ 的行为（这个方法本身就是资产）

TaCZ 的 jar **4679 个条目、0 个 .java** —— 没有源码，**但也没有混淆**
（`renderBonesVBO` / `meshAncestorBones` / `scopeViewRadiusModifier` / `isScopeOcular`
这些名字都是原始可读的）。作者只是没写格式文档。

**没有 JDK / javap**，所以自己写了一个常量池 + 字节码解析器：

```bash
# 反汇编任意类（jar 路径写死在文件头 MODS 常量里，类名必须带 .class 后缀）
python work/jdis.py com/tacz/guns/client/model/BedrockGunModel.class allAttachmentRender

# 列 jar 内类名（按关键字）
python work/jls2.py FirstPerson Arm

# 扫常量池字符串
python work/jarstr.py

# 反汇编控制器
python work/jarbc.py com/tacz/guns/api/client/animation/AnimationController.class runAnimation
```

为什么不用 Fernflower 反编译：Forge 的映射会把方法名变成 `m_252880_` 这种占位符，
而**读字节码 + 常量池比读源码更准**（源码/文档可能过时、可能写错 —— `model_type` 就是典型）。

三条实战结论都是这么拿到的：

* `Animations.writeBedrockTranslation` 里每条关键帧乘 `0.0625` → position 单位定论（§4）。
* `BedrockPart.translateAndRotateAndScale` 顺序 `translate(off) → translate(pivot/16) → rotate`。
* `allAttachmentRender()` 的 `type != NONE && type != SCOPE`，以及三个
  `scopeHiddenRender` 谓词的**极性**（`sight` = 没装瞄具时可见）——
  这条只能从字节码读出来，官方文档没有。

`default_state_machine.lua` 是**明文**，直接在 jar 里的
`assets/tacz/scripts/default_state_machine.lua`，已解包到 `work/dsm.lua`。
"游戏在什么时候调哪个动画"查它最快。
